# 文件、搜索、子进程与上传边界

## 原生安全文件模块

`write` / `edit` 在独立 Worker 中通过 Node-API 模块进行文件操作，不依赖实验性的
`bun:ffi`。POSIX 使用目录描述符及 `openat`、`renameat`、`linkat`；Windows 持有
目录链句柄，拒绝 reparse point，并通过文件句柄执行原子替换。临时文件不会跟随
最终目标链接，新建文件也不会覆盖审批后才出现的同名文件。

审批和 sandbox 路径检查依然执行。合法链接先解析为规范目标，再经过同一原生边界。
原子替换需要目录写权限；仅支持普通文件。Windows 目前限本地盘路径，不支持 UNC、
设备路径或 NTFS alternate data stream；不支持安全操作的文件系统会明确报错。
POSIX 新建文件需要同目录硬链接支持，以保证提交时不覆盖并发创建的文件。
目录句柄防止路径被链接替换后重定向到另一目录，但不是对同 UID 任意文件系统修改的隔离。
POSIX 仍依赖受信的父目录权限：具有目录写权限的其他进程可移动整个目录、修改临时文件，
也可在身份检查与 rename/unlink 之间替换目录项。需要抵御此类攻击时，应使用隔离的
OS 身份和不可由攻击者修改的目录；不能把应用层路径检查当作该隔离保证。
原文件的基本权限、DACL/普通 ACL、所有者、Windows 完整性标签及有界扩展属性会被保留；
无法安全保留时会拒绝替换。本工具不替代需要完整系统审计 SACL 备份的管理工具。
原子替换会改变文件身份/inode。Windows EFS 文件会保留原状并明确拒绝原子编辑，
避免丢失加密接收者或把内容降级为明文；请使用支持 EFS 语义的编辑器。
macOS 带文件系统压缩标记的文件也会明确拒绝原子替换，避免复制旧的派生压缩数据。
扩展元数据限制为 128 项/64 KiB；派生的权限或内容签名不会被复制为新内容的有效签名。

源码开发先安装 C/C++ 编译工具，再运行：

```sh
pnpm install
pnpm build:native
pnpm dev:tui
```

可用 `CXX` 指定编译器可执行文件。Windows 支持 LLVM-MinGW，以及开发者终端中的
MSVC（`CXX=cl`）；macOS 使用 Xcode Command Line Tools；Linux 使用 GCC/Clang。
`node-api-headers` 仅为开发依赖，运行时不下载编译器或执行源码构建。

正式 npm 包包含五个平台的预编译模块；独立版将对应模块内嵌到可执行文件中，
本文件模块不要求使用者额外编译器，原有 node-pty/平台沙箱前置条件不变。
源码的全套 `pnpm test` / `pnpm build` 会先检查或构建本机模块。
构建缓存使用源码、头文件和目标指纹，并检查产物的 CPU 架构和 SHA-256。

```sh
pnpm build:npm:local  # 仅本机验证，生成 private、受 os/cpu 限制的包
pnpm test:npm
```

正式跨平台 npm 打包仍使用 `pnpm build:npm`，要求五个平台对应本轮源码的 CI 产物齐全；
缺少任何平台会失败，不会悄悄发布缺少原生模块的包。
`release` 工作流的手动运行默认 `build_only=true`，验证五平台及完整 npm 包并保留产物；
该模式不申请 npm 发布身份，也不运行 npm 或 GitHub Release 发布任务。
官方 Linux 原生构建使用 manylinux glibc 2.28 基线；macOS 模块使用 13.0 部署目标，
避免无意抬高既有 Node/Bun 运行要求。源码自行构建的 ABI 取决于本机工具链。

## 资源预算

| 范围 | 默认边界 |
| --- | --- |
| write 输出、edit 源文件/输出 | 64 MiB |
| edit 单个 old/new 参数 | 1,000,000 UTF-8 字节 |
| edit 替换次数 | 1,000,000 |
| 搜索 pattern/glob | 4,096 字符，glob 必须相对获准根目录 |
| grep 单文件 | 1,000,000 字节，读取前和读取时检查 |
| grep 累计扫描 | 64 MiB、20,000 个文件、15 秒 |
| grep 单文件正则匹配 | 独立 Worker，1 秒，超时终止 Worker |
| 模型展示文本 | 2,000,000 字符，超出会明确标记截断；原始 SDK 结果不变 |
| 结构化文本 parts | 每项 1,000,000 字符，合计 2,000,000 字符 |

正则保留 JavaScript 语义（含反向引用/环视），没有换成更弱的正则子集。
grep 的源文件读取也通过原生目录句柄边界进行，并在开始正则匹配前释放文件句柄。
遇到预算错误应缩小 `path`、`glob` 或 pattern；不会把预算耗尽伪装成“没有更多结果”。
这些是应用级预算，不能替代 OS 对故障设备或内核 I/O 的处理。

## 外部 CLI / ACP 环境与输出

外部代理仍需要启动审批。默认环境仅保留系统、语言、终端、配置目录和标准代理变量，
不再全量复制宿主环境。代理 URL 可能包含代理认证；保留它是保留该网络连接配置，
不等于实现了凭据保险库。HOME/配置目录仍可被受信 CLI 使用，本设计也不隔离宿主可读文件。

如某个后端确实需要宿主中的 API key，可按名称授权，不把值复制到项目配置：

```json
{
  "subagents": {
    "providers": [
      {
        "type": "command",
        "name": "my-agent",
        "command": "my-agent",
        "inheritEnv": ["MY_AGENT_API_KEY"],
        "timeoutMs": 120000
      }
    ]
  }
}
```

`env` 仍支持显式宿主配置；`inheritEnv` 中缺失的变量会明确报错。loader 注入变量
（如 `NODE_OPTIONS`、`LD_*`）不能通过这两种途径传入；需要相关启动参数时，
应配置明确的解释器和参数。不会记录环境变量值。

| 外部进程资源 | 上限 |
| --- | --- |
| 每次 stdout / stderr 总量 | 各 2 MiB |
| stdout 单行 | 256 KiB |
| stdout 事件 | 2,048 条 |
| stderr 尾部缓存 | 8,192 字符 |
| 默认进程截止时间 | 120 秒，可用 `timeoutMs` 调整 |

超限会失败并尝试终止所属进程树，不会返回“截断后的成功”。最终答案仍保留既有
32,768 字符边界。该机制限制父进程接收的数据与执行时间，不是外部 CLI 的 OS 级
CPU/内存隔离；外部可执行程序仍须由宿主信任。

Windows `.cmd` 通过 `cross-spawn` 处理参数边界；无法安全表达的引号、`%`、`!`、
`^` 和换行参数会被拒绝。此类参数或目录名应配置实际原生可执行文件/解释器。
POSIX 不再支持 `shell:true` 的隐式拼接；可显式配置 shell 可执行文件，并将提示投递到 stdin。

## 上传

上传先流式解析并限制 multipart，再序列化配额检查和文件提交。默认每文件 20 MiB、
请求体 32 MiB、16 个文件、工作区累计 512 MiB/256 个条目，同时最多两个请求。
请求 deadline 为 30 秒。宿主 SDK 可通过 `ServerOptions.uploadLimits` 调整预算；
普通用户可通过删除不再需要的 `.ringko/uploads` 文件释放配额。
空的 `.upload.lock` 是保留的内核锁文件，不计入附件配额。不同后端实例也通过此锁
协调同一目录，同一 JS 运行上下文另有在首个 await 前取得的共享预留，避免不同
UploadManager 实例并行进入配额事务；进程退出时内核释放锁，不依赖 PID 文件或
危险的陈旧锁回收。

上传保留二进制内容、使用随机唯一名称，拒绝逃出工作区的链接目录。部分提交失败时，
只清理本次创建且身份仍匹配的文件；清理失败会明确报告并写诊断。不会自动删除旧附件，
以免破坏历史会话的文件引用。项目切换和后端关闭会考虑活动上传。

## 更新信任模式

本轮按既有策略保留 HTTPS、官方发布来源、SHA-256 和版本检查，没有增加签名或
构建证明要求。校验和验证内容一致性，不能提供独立于发布方的真实性保证；发布方
账号/构建环境仍在信任边界内。npm 所需的原生依赖构建脚本也没有被简单禁用。
