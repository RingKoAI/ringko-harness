## 2. 风格核心

核心是“以任务对话为中心的终端工作台”：用留白、缩进、状态和少量颜色建立层级，
将复杂信息逐步展开，而不是为每条消息堆叠边框与元数据。

| 元素 | 参考实现的做法 | RKH 调整方向 |
| --- | --- | --- |
| 正文 | 使用终端正常文本颜色，长回答主要靠 Markdown 组织 | 正文保持最高可读性，操作提示使用弱化色 |
| 用户消息 | 单独背景、适量间距，形成回合边界 | 用户块统一内边距和换行宽度 |
| 助手消息 | 正文优先，按需要显示回合标记 | 标记只放在回合开头，续行和流式片段不重复标记 |
| 工具调用 | 工具名与目标在一行，结果缩进，探索操作可合并 | 降低重复的 Completed、Done、快捷键提示 |
| 输入区 | 无左右封闭边框，以水平线分区，颜色表达模式 | 普通输入用中性边界，RKH 品牌色用于重点 |
| 底部提示 | 根据当前操作切换，短屏隐藏可选信息 | 统一提示出口，减少两行重复的固定快捷键 |
| 面板 | 单一分隔线、标题、说明、内容、操作提示 | 选择器、认证、授权、提问共用呈现规范 |

色彩使用语义 token：品牌、正文、弱化文本、边界、选中、成功、失败、警告和用户背景。
失败等重要状态同时保留文字标记，不能仅靠颜色区分。

## 3. 目标布局

以下是 RKH 的示意布局，不是参考项目截图或已经实现的画面。

```text
RKH · 当前模型 · 项目                         启动时的精简介绍

> 用户的问题                               用户回合背景

● 助手正文                                 Markdown 与代码块

● 搜索 3 处，读取 5 个文件                  连续探索摘要
  └ 最近结果或失败原因                     需要时展开原始调用

● Bash(git status)
  └ 命令结果摘要

执行中…                                    临时状态 / 待处理任务
────────────────────────────────────────
> 当前草稿                                 固定输入区，可多行
────────────────────────────────────────
Enter 发送 · Alt+Enter 换行                 按当前上下文切换
项目路径 · 会话                    模型 · 思考深度
```

默认会话仍采用当前备用屏布局。状态、任务和输入区共享高度预算，聊天区获得剩余空间。
短屏时优先收起辅助状态和任务详情，保留可操作的输入或弹窗，以及必要的消息上下文。

## 4. 关键处理规则

### 4.1 消息与工具：显示投影独立于真实事件

当前 `transcript-layout.ts` 为每次工具调用生成多行状态、结果和展开提示，
连续探索容易把助手回答挤出视口。

调整为：原始 `ReplItem` / 后端事件 → 显示分组 → 按终端宽度排版 → 视口渲染。

- 仅合并同一显示上下文中相邻的读取、列举和搜索操作。
- 用户消息、助手正文、授权请求、错误和任务切换都打断分组。
- 写文件、编辑、Shell 等操作保留独立标题，便于追踪目标和结果。
- 显示分组保留原始调用 ID，展开时可以查看完整调用与结果。
- 运行中、完成、失败、取消和恢复后状态未知不能混为同一状态。
- 成功、失败以真实事件为准，不因展示动画或后台仍在运行就延迟、伪造执行状态。
- 聚合是显示层行为；存储、审批、工具执行次数和模型上下文仍使用真实事件。

### 4.2 输入区：编辑、补全、运行状态分别管理

当前已有多行编辑、Unicode 字素处理、括号粘贴、历史与草稿恢复，可作为基础。

- 普通输入使用中性水平线；`!` Shell 输入显示明确的模式提示。
- 补全开启时，上下键操作候选，Tab 补全，Esc 先关闭候选。
- 编辑器聚焦时，输入和粘贴事件只进入编辑器；弹窗聚焦时不写入隐藏草稿。
- 显示当前输入视口上下还有多少隐藏行，多行内容增长时仍保留聊天区域。
- 运行时保留正在编辑的草稿，明确提示当前支持的操作。
- 当前运行期间 Enter 不提交的行为应有可见说明，避免看起来像按键失效。
- 大段粘贴的折叠预览若加入，需要将完整文本与预览分离，提交时使用完整文本。
  这涉及额外编辑状态，应独立实现，不能只截短输入字符串。

### 4.3 底部提示：一个出口，按上下文选择

当前 `PromptInput` 和 `StatusBar` 各有固定提示行。统一为优先级明确的提示模型：

1. 授权或提问：当前选择、确认、拒绝或返回。
2. 补全或选择器：导航、补全 / 选择、关闭。
3. 退出确认：二次按键提示。
4. 执行中：中断和当前可用动作。
5. 普通编辑：提交、换行及必要帮助入口。

持久状态展示项目、会话、模型与思考深度；临时提示与持久状态分别排版。
快捷键文字从真实绑定生成。窄屏按优先级省略，不能显示被截断的半个按键说明。
用量等信息需要来自实际数据源，不能以估算值冒充精确状态。

### 4.4 滚动：跟随最新与阅读历史是两个状态

当前 `Transcript` 通过“离最新内容多少行”的 offset 截取页面。
同一个 offset 下追加新内容会改变所见文本，因此阅读历史时可能发生位置漂移。

- 跟随模式：新增流式输出自动展示最新内容。
- 历史模式：记录可见消息及其内部行位置，新增内容不拉动当前阅读位置。
- 历史模式有新输出时显示“有新内容 / 返回最新”的提示。
- 返回底部后恢复跟随；切换会话和任务时明确重置或恢复各自的滚动状态。
- 宽度变化导致重新换行时，尽量用消息锚点恢复阅读位置，而不是沿用旧行数。
- 展开工具详情也应保持视口锚点，避免突然跳到其他回合。

### 4.5 面板与授权：统一框架，输入归属明确

建立共享的面板结构：分隔线 → 标题 / 描述 → 内容 → 操作提示。
嵌套内容使用同一个外框，避免重复圆角边框占据空间。

- 任一时刻有明确的活动输入层，聊天输入、候选、弹窗、授权不能同时处理同一按键。
- 关闭面板后恢复原草稿与光标位置；后台消息到达不应意外关闭面板。
- 列表导航焦点与已选择值是不同状态，当前项也不同于光标高亮项。
- 授权说明完整展示工具、目标、原因与授权范围；一次、会话、持久规则须明确区分。
- 当前 `ApprovalDialog` 将 Enter 直接映射为批准，但底部提示只写 y/n。
  这是需要明确设计的实际行为差异：至少使提示和绑定一致；若改成选项导航，
  则明确默认项并增加回归验证，不能把权限交互变化隐藏在样式改动中。
- 展示层继续调用现有审批回调和后端规则，授权策略与界面布局保持独立。

### 4.6 流式渲染与性能

当前 `Transcript` 在 items 改变时重新计算整段 `transcriptLines`，
因此只显示一屏并不意味着只计算一屏。

- 已完成消息缓存排版结果，缓存键包含消息内容版本、宽度和展开设置。
- 仅更新仍在流式生成或工具执行中的消息；视口不相关的动画不驱动全局刷新。
- 换行宽度按终端单元格计算，包含中文、组合字符、Emoji 和缩进占用。
- 缓存有上限；宽度和主题变化时失效，不能无限保存历史布局。
- 对超大输入、输出使用有界预览及按需展开，同时保留完整原始数据。
- 保留现有终端控制字符清理，新增摘要、状态栏、标题等也需经过显示净化。

## 6. 验收标准

- 在 120×30、80×24、40×12 终端尺寸下检查布局；不越界，关键操作可见。
- 中英文、长路径、组合字符、Emoji、多行粘贴及宽度变化下光标位置正确。
- 连续读文件和搜索形成摘要，原始调用与结果展开后可追溯。
- 工具失败、取消和恢复后的未知状态不会显示为成功。
- 流式生成时可上翻阅读，内容追加不改变当前阅读锚点，返回最新后重新跟随。
- 模型 / 会话选择、授权、提问、认证关闭后保留草稿，按键不穿透到其他层。
- 终端控制序列不会通过消息、工具输出、路径、标题或摘要注入屏幕。
- TUI 与 WebUI 的会话、消息、审批、任务同步保持有效。
- 运行相关单元与交互测试、类型检查、二进制和 npm 包构建；
  使用真实终端检查最终布局与交互，不能以测试文本包含某个单词代替视觉验收。
