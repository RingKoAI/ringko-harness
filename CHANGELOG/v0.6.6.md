# v0.6.6

- Put the composer's send/stop action in the input row, keep the tool row on
  one horizontally scrollable line, and expose message actions on touch devices.
- Make busy submissions queue explicitly: toast on enqueue, a numbered queue
  panel with edit/remove/resume, and a pending count on the send button.
- Serve the WebUI entry document with `no-cache` and content-hashed assets as
  immutable so a rebuilt frontend is never pinned to previous asset names.
- Add a message copy affordance for both user and assistant messages: success
  chrome only after the write resolves, duplicate-click guard, one-second
  revert, and a selection fallback when the async clipboard is unavailable.
- Render Mermaid fences with theme-aware re-rendering, CSS-safe per-diagram ids,
  responsive SVG sizing, and a source fallback when a diagram cannot render.
- Add a task view switcher that opens a subtask's live event stream inline, and
  a task-id cancellation endpoint so a running subtask can be stopped without a
  cached job summary. Stopping the run still cancels its whole task tree.
- Collapse each step's tool calls into one summary row with activity counts,
  failure count and live running name; the group opens while running, after a
  failure, or when detailed tool output is enabled.
- Add sidebar session search with a match/empty state, keep session actions
  reachable on coarse pointers, raise touch target height on small screens, and
  make the sidebar width draggable, keyboard-resizable and persisted locally.
- Render `edit` tool calls as a bounded unified diff derived from their exact
  before/after text, with per-call and per-step added/removed line counts.
- Use the app's ring mark, matching the favicon, in the sidebar brand block and
  the landing header instead of a letter placeholder.
- Replace the Settings theme buttons with a labelled dropdown.
- Follow the transcript tail while the reader stays at the bottom, keep their
  position after scrolling up, and show a jump-to-latest control (with an unread
  dot) that re-enables following when clicked.

- Move usage statistics into Settings and add workspace/session date, provider,
  model and call-type filters, token/cache summaries, duration metrics, trends,
  grouped statistics and paginated call history. Deduplicate inherited fork
  usage, preserve unknown metrics, and bound workspace-local log scans.
- Add a real Windows restricted ConPTY host, preserving token restrictions,
  Job Object cleanup, input/resize and streamed exit/output semantics.
- Support Windows additional writable roots, including read-only downgrades
  that cannot reuse earlier write grants. Preserve cmd command-body quoting.
- Embed native helper source in bundles and standalone binaries, build it in
  private staging, and atomically install the content-addressed executable.
- Restrict inherited handles, filter ambient credentials/agent environment,
  and retain explicitly configured connector credentials.
- Reject loader/profiler environment injection before the runner starts, pin
  runner/system-tool paths, and select only the system Windows compiler.
- Apply sandbox defaults to direct shell/write/edit tools, embedded REPL human
  commands, workspace Git review, and the local MCP connection-test endpoint.
- Restrict Seatbelt temporary writes to the private canonical temp directory.
- Require host-settings endpoint/tool authorizations for remote MCP before
  connecting or invoking tools; do not trust project-supplied permissions or
  server hints. Reject redirects and cross-origin SSE endpoints.
- Track the actual local MCP process policy and reject weaker-process reuse
  under read-only. Reject pending stdio requests promptly on process exit.
- Default local MCP working directories to their workspace instead of the
  host process's launch directory when `cwd` is omitted.
- Add native ConPTY, extra-root, child-token, timeout, standalone relocation,
  remote authorization and credential-forwarding regression tests. Preserve
  the session-compaction replay regression checks.

The write-confinement, filesystem alias/TOCTOU, network, Windows named-pipe and
temporary-directory cleanup limits are documented in `SANDBOX.md`.
