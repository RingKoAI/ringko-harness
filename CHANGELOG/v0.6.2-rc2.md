# v0.6.2-rc2


- Forward shared model context limits to headless `run`/`loop` and standalone
  embedded REPL hosts, including catalog metadata and explicit overrides.
- Skip automatic public catalog matching for private/local deployments unless
  explicitly mapped. Remote catalog mirrors require HTTPS; loopback mirrors
  may use HTTP for local development.
- Use Plan/steps terminology in the UI while preserving the frozen
  `session/todo` event name and the existing `/todos` command.
- Check the CLI manifest against `bun.lock` during tests and npm packaging.
- Register one live backend per workspace/config in `~/.ringko/backends/`. TUI
  and `serve` now discover and reuse that owner instead of starting a second
  backend; stale owners are reclaimed and a live foreign owner rejects startup.
  The legacy 8787 port remains a discovery fallback for pre-upgrade servers.
  `run`/`loop` and embedded REPL execution remain local for now.
- Separate MCP registration, discovery and execution: `GET /api/mcp/connected`
  now only reads the backend snapshot instead of starting servers; `/api/info`
  reports the effective MCP tool set; MCP configuration changes are rejected
  while sessions are running. Add end-to-end coverage for MCP and skills across
  registration, agent discovery and recorded execution.
- Return a clear "no longer available" error when a discovered skill's
  `SKILL.md` disappears before execution.
- Discover shared skills in ancestor workspaces inside the user home, so a
  nested repository sees skills installed by its parent projects directory.
  Project-root skills still win on name collisions.
- Make `ringko` and `serve` open the active registered project instead of the
  launch directory; `--workspace` remains an explicit compatibility override.
  With no project registered, the launch directory is a first-run bootstrap
  only. Skills and MCP discovery follow the selected project.
- Rebuild current instruction-file context before each main-model request and
  after compaction, without relying on summaries or accumulating stale rule
  blocks. Bound instruction reads and reject overlapping run/compaction calls.
- Show primary-call generation speed, cache hit rate and context usage in a
  compact composer footer; remove the model subtitle from the sidebar header.
- Default host execution to `sandbox.mode = "workspace-write"` and keep
  `danger-full-access` explicitly opt-in. File writes are bounded in-process;
  shell and local stdio MCP processes run through bubblewrap,
  Seatbelt, or a native Windows restricted-token runner. Missing runners fail
  closed. The Windows runner uses capability-SID ACLs and low-integrity labels;
  its reads remain unconfined and grandchildren that create piped stdio may
  fail with `EPERM`. Remote MCP tools without a positive read-only declaration
  are withheld under `read-only`, while `workspace-write` keeps them
  approval-gated because their remote side effects cannot be host-confined.
- Make compaction replacement-aware: record the replaced surface sequence
  numbers, remove only that span during replay, and retain the untouched recent
  tail. History and replay now share one compacted-surface derivation, the cut
  never orphans a tool result, and repeated compactions replace the previous
  checkpoint instead of accumulating summaries. Older summary-only events keep
  their legacy replay behavior.



## Known limitations

- Windows sandbox enforcement is partial: reads remain unconfined, and
  grandchildren that create piped stdio may fail with EPERM. Interactive PTY
  terminals fail closed on Windows until a confined ConPTY bridge is added.
- Linux bubblewrap and macOS Seatbelt paths are covered by CI tests but were not
  executed locally on this Windows host.
- Windows shell execution does not yet support additional writable roots.
